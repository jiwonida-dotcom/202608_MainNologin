Final Visual Design Summary

이번 패스는 새 요소를 더한 것이 아니라 중복·노이즈를 걷어낸 작업이다. 카드 안의 중복 CTA, 2열에서 정렬을 흐리던 chevron, 오독되는 아이콘, 토큰 밖 색상 하나 — 네 가지를 제거했고 그 결과 M-05 카드가 150 → 124px로 조여졌다. IA·모듈·순서·우선순위는 일체 변경하지 않았다.

위계 체계 4축 — 크기(제목 22/19/17) · 형태(P0 풀블리드 리스트 / P1 인셋 카드 / P2·P3 평면) · 깊이(elevation은 P1에만, 화면당 2회) · 밀도(P0 24 / P1 20 / P3 16px 패딩). 첫 화면에는 그림자를 가진 요소가 하나도 없다.

Design Readiness — 이번 단계 판정

제안 가능. 4폭 전부 가로 스크롤 0 · 줄바꿈 0 · 좌측선 단일 · 대비 실패 0. 토큰이 운영 화면 실측값이라 :root 교체 없이도 제안할 수 있는 상태다.

단서 3가지 — ① 토큰은 운영 화면 실측(OBSERVED)이지 공식 디자인 토큰 문서로 확인된 값이 아니다 ② Pretendard는 자체 호스팅이라 Artifact에서 로드되지 않는다(로컬 설치 환경에서만 운영 폰트로 렌더) ③ 상품·이벤트·휴대폰은 전부 SAMPLE이며 코드 주석과 화면 하단에 고지돼 있다.

이번 패스에서 발견·수정한 것

① 푸터 앱 버튼 터치 타깃 회귀 — 인라인 필로 축소하면서 38px이 되어 44px 규칙을 어겼다. 자동 감사로 적발해 복구. 이런 회귀는 눈으로 못 잡는다.
② 중복 CTA — "자세히 보기"가 배너·가입안내·셀프개통에 3회 등장.
③ 2열 chevron 정렬 노이즈 · ④ 오독되는 별 아이콘 · ⑤ 토큰 밖 색상(교체 시 누락될 값이었다)

QA에서 고친 것 — 실제 렌더 검증 기준

⓪ 대비 자동 감사 — 바이올렛 교체 후, 렌더된 화면(M-06 펼침 포함)의 모든 텍스트 노드를 순회하며 실제 계산된 전경·배경색으로 대비를 측정했다. 실패 0건. 이 과정에서 #8C63F4가 흰 텍스트 4.03:1이라 채운 버튼 배경으로 못 쓴다는 것을 확인해 GNB 로그인 버튼을 --brand-600(6.22:1)으로 바꾸고, 로고는 큰 텍스트 기준을 넘기도록 20px로 올렸다. 배너 텍스트는 그라디언트 위라 자동 감사 대상이 아니어서 스크림 적용 후 최악 지점을 별도 계산했다 — 8.69:1.

① 대비 재검증 — 팔레트 전 조합을 계산했다. --n-400 #939DA6이 2.76:1로 나와 텍스트에서 완전히 제외하고 --icon-deco로 이름을 바꿔 장식 전용임을 강제했다. 푸터 잔글씨는 --text-3이 회색 배경에서 4.30:1로 미달해 --text-2(7.57:1)로 올렸다.

② 배너 오버레이 컨트롤 철회 — 좌우 화살표를 배너 위에 올렸더니 슬라이드 제목을 그대로 가렸고, 44px 히트 영역을 ::after로 확장하자 인접 버튼끼리 히트 영역이 겹쳤다. 오버레이를 포기하고 배너 아래 컨트롤 행으로 되돌렸다 — 인디케이터·이전/다음·카운터·정지가 모두 44px로 들어간다. 세로 공간 44px을 쓰지만 배너 아래는 AtF 밖이라 첫 화면 예산에 영향이 없다.

③ 터치 타깃 자동 감사 — 화면의 모든 button·input을 순회하며 ::after 확장분까지 합산해 실측했다. 푸터 링크 4개가 40px로 미달해 44px로 올렸다. 남은 미달은 캐러셀 인디케이터(24×44)뿐이며, 이는 dot 간격을 벌리지 않으면 히트 영역이 겹치기 때문이다 — AA 최소(24×24)를 충족하고 44px 경로는 이전/다음이 대신한다.

④ 스와이프와 세로 스크롤 충돌 — 배너를 세로로 쓸어도 캐러셀이 반응했다. touch-action:pan-y와 축 판정(가로 이동이 세로보다 클 때만 슬라이드)으로 분리하고, 스와이프 직후 클릭을 캡처 단계에서 억제했다.

⑤ 슬라이드 카피 줄바꿈 — 제목이 2줄로 넘쳐 배너 구성이 무너졌다. max-width를 ch 단위(한글에서 부정확)에서 백분율로 바꾸고 카피를 1줄 분량으로 줄였다.

⑥ M-03 행 높이와 여백 — 보조 설명 추가로 60px을 유지할 수 없어 64px로 조정했다. 대신 섹션 여백을 조여 배너 상단을 661px로 끌어올려 스필오버를 확보했다(CH-13).

5

진입 맥락 상태 — 가입 완료 후 복귀

entry context · RS-01

PHASE 6에서 상태로만 정의되고 화면으로 구현되지 않았던 항목이다 — "가입 완료 후 복귀 · 완료 맥락 인지 — 신규 가입 유도를 반복하지 않음 · /util/join/joinComplete 4,654 sessions". PHASE 11에서 이 공백을 최소 범위로 채운다.

먼저 · 이 4,654 sessions는 무엇을 마친 사람인가

리퍼러 경로는 util/join 하위다. 현행 전체메뉴에서 /util/join/joinIntro는 "회원가입"으로, 상품 가입은 /shop/mobile/mobileJoinIntro로 서로 다른 경로 체계에 있다. 따라서 이 세션들은 사이트 계정 생성을 마치고 돌아온 것으로 읽는 편이 경로 체계와 일치하며, PHASE 6의 "신규 가입 유도"는 개통이 아니라 계정 생성 유도를 가리킨다.

CONDITIONAL 완료 페이지의 실제 내용은 확인하지 않았다. 이 해석이 뒤집히면 아래 RS-1의 대상도 함께 바뀐다.

이 상태에서 알 수 없는 것

4,654 sessions는 규모일 뿐, 이들이 무엇을 하러 돌아왔는지는 관측되지 않았다. UNVERIFIED 현재 태깅에는 진입 맥락 차원이 없어서, 복귀 세션만 떼어 다음 행동을 볼 수단이 없다. 그래서 이 상태는 목적을 추측해 화면을 재구성하지 않고, 논리적으로 무의미해진 것 하나만 걷어낸다. 나머지는 측정을 붙인 뒤 판단한다(아래 측정 제안).

RS-01 · 상태 정의

항목정의
상태 IDRS-01 — 가입 완료 후 복귀 (entry context: joined)

기본값일반 진입. 판정에 실패하면 현행 화면을 그대로 보여준다(안전한 쪽이 기본)

ID대상처리근거

하지 않는 것 — 그리고 그 이유

검토한 변형기각 사유
로그인 영역 강조 확대복귀 목적이 로그인이라는 관측이 없다 UNVERIFIED. 로그인은 이미 최상위 진입점이며, 맥락에 따라 크기가 변하면 같은 화면이 두 얼굴을 갖는다
개통·가입 안내(M-05) 우선 배치계정 생성 완료가 상품 가입 임박을 뜻한다는 근거가 없다. 두 경로는 체계가 다르다. 배치 변경은 구조 변경이기도 하다
완료 확인 · 환영 문구 노출신규 콘텐츠 영역 추가 금지 · 콘텐츠 총량 증가 금지 DD-14. 완료 안내는 완료 페이지의 역할이다
전체메뉴 안의 회원가입 항목도 억제전체메뉴는 사용자가 스스로 열어 찾는 곳이다. 찾은 항목이 없으면 그 자체로 마찰이 된다. 상시 노출된 부가 링크(RS-1)와 성격이 다르다
M-10 팝업 억제방향은 타당하나 현재 운영 팝업의 내용·조건·주기를 확인하지 못했다 DV-03. "가입 유도 성격 팝업이 있다면 이 맥락에서 제외한다"는 조건부 제안으로만 남긴다

측정 제안 — 현행 태깅에 없는 항목

아래는 제안이며 확정된 이벤트 사양이 아니다. 현재 MAIN_NOTLOGIN 태깅에는 진입 맥락을 구분하는 차원이 없어, 복귀 세션만 분리해 행동을 보는 것이 불가능하다. 이 측정이 붙기 전에는 RS-1 이상의 변형을 확정하지 않는다.
